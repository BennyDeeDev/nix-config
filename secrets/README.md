# Secrets Management

This repo uses [sops-nix](https://github.com/Mic92/sops-nix) with [age](https://github.com/FiloSottile/age) encryption. The dev master identity lives on a YubiKey PIV slot via [age-plugin-yubikey](https://github.com/str4d/age-plugin-yubikey). Each NixOS host holds a standalone age key at `/var/lib/sops-nix/key.txt`, auto-generated by sops-nix on first activation. This decouples sops from SSH entirely — sshd can be enabled or disabled on any host without affecting secret decryption.

## Architecture

- **Dev edit identity**: YubiKey PIV slot 1, age-plugin-yubikey, pin-policy=once, touch-policy=always.
- **Host decrypt identity**: split across two layers when Home Manager is used:
  - System level: standalone age key at `/var/lib/sops-nix/key.txt`, auto-generated by sops-nix on first system activation if missing (`sops.age.generateKey = true`). Used by NixOS activation to decrypt password hashes and other system secrets.
  - Home level (HM hosts only): standalone age key at `~/.config/sops/age/keys.txt`, auto-generated by the HM sops module on first HM activation if missing (`sops.age.generateKey = true` in `nix/home/sops.nix`). Used by HM `sops-nix.service` to decrypt home-level secrets (rclone, etc.).
  Both pubkeys must be enrolled as recipients in `.sops.yaml`. Hosts without HM use only the system key. Routine rebuilds/reboots decrypt unattended — no YubiKey needed.
- **Secret files**: encrypted YAML under `nix/secrets/`, scoped per-file via `.sops.yaml` `path_regex`.
- **`.sops.yaml`**: at repo root. Maps `path_regex` to recipient lists. Consulted at encryption time only; decryption trusts the recipient list baked into each encrypted file's header.

## One-time YubiKey setup

On a new or factory-reset YubiKey, the public factory defaults are PIN `123456`
and PUK `12345678`.

```
ykman piv access change-pin
ykman piv access change-puk
ykman piv access change-management-key -a TDES --generate --protect
```

The `-a TDES --protect` flags are REQUIRED (not optional) for `age-plugin-yubikey` to accept the key. `age-plugin-yubikey` only supports TDES — see https://github.com/str4d/age-plugin-yubikey/issues/92. AES is not yet supported.

Mgmt key under `--protect` is PIN-wrapped; you don't store it anywhere. PIN is the only credential needed going forward.

## Generate the age identity

```
age-plugin-yubikey --generate
```

Output (save both):
- `age1yubikey1...` line — the recipient (public key). Goes into `.sops.yaml`.
- `AGE-PLUGIN-YUBIKEY-1...` line — the identity (pointer to slot, NOT the private key). Goes into `nix/home/sops.nix`'s `identity.txt`.

## Enroll a new host

One-time per host. Two phases: get an age key onto the host, then extract its pubkey for `.sops.yaml`.

### Phase 1: Bootstrap the age key

**First host only (fleet bootstrap)**: sops-nix's `generate-age-key` activation script is gated behind `cfg.secrets != {}` (see `modules/sops/default.nix`). With zero secrets declared, it never fires. So the very first host needs manual keygen to break the chicken-and-egg — this happens exactly once across the lifetime of the fleet:

```
ssh <host>
sudo mkdir -p /var/lib/sops-nix
sudo nix shell nixpkgs#age -c age-keygen -o /var/lib/sops-nix/key.txt
sudo chown root:root /var/lib/sops-nix/key.txt
sudo chmod 600 /var/lib/sops-nix/key.txt
```

**Subsequent hosts**: once `sops.secrets.*` is declared on the host and deployed, `sops.age.generateKey = true` auto-generates `/var/lib/sops-nix/key.txt` on first activation. No manual `age-keygen` needed. The first deploy will fail to decrypt (host's pubkey isn't in `.sops.yaml` yet — expected); the key file IS created during that deploy, so proceed to Phase 2 to extract and enroll.

### Phase 2: Extract pubkey and enroll

```
ssh <host>
sudo nix shell nixpkgs#age -c age-keygen -y /var/lib/sops-nix/key.txt
```

This prints the host's `age1...` public key. Paste it into `.sops.yaml` under the matching `&<host>` anchor:

```
sops updatekeys nix/secrets/common.yaml nix/secrets/desktop.yaml    # run on dev with YubiKey plugged in
git add .sops.yaml nix/secrets/*.yaml
git commit
```

Redeploy the host. Decryption now succeeds.

## Edit a secret

```
# plug in YubiKey
export SOPS_AGE_KEY_FILE=<path to identity.txt>    # HM already sets this via sessionVariables
sops nix/secrets/common.yaml
# editor opens; on save, file is re-encrypted to all recipients in .sops.yaml for that path
# touch the YubiKey when prompted (if touch-policy=always)
git add nix/secrets/common.yaml
git commit
```

## Higher-security variant: desktop decrypts via YubiKey

The default config uses each host's standalone age key at `/var/lib/sops-nix/key.txt` for unattended decryption (`sops.age.keyFile + sops.age.generateKey`). For desktop, you can instead require the YubiKey to be present at every rebuild/reboot by overriding `sops.age.keyFile` to point at the age-plugin-yubikey identity. Trade-off: YubiKey must be physically inserted + PIN typed at every decrypt, including boot-time `neededForUsers` (no YubiKey at boot = user creation fails = login impossible). Only worth it for a workstation you sit at and treat as high-security.

### To enable on desktop

In `nix/hosts/desktop/default.nix`, override the shared `sops.age.keyFile` from `nix/modules/sops.nix`:

```nix
{ pkgs, lib, ... }:
{
  sops.age.keyFile = lib.mkForce null;
  sops.age.generateKey = lib.mkForce false;
  sops.age.sshKeyPaths = lib.mkForce [];   # already empty, but explicit
  environment.etc."sops/age/identity.txt".text =
    "AGE-PLUGIN-YUBIKEY-17Z2J5Q5Z709P64S7VFQZT";
  environment.systemPackages = [ pkgs.age-plugin-yubikey ];
  services.pcscd.enable = true;             # already enabled
  sops.age.keyFile = "/etc/sops/age/identity.txt";   # point at the yubikey identity
}
```

Then enroll desktop's YubiKey identity as a recipient in `.sops.yaml` — the `age1yubikey1q...` already listed under `&dev` serves this purpose. No separate recipient needed; the same YubiKey pubkey does double duty as both the admin edit identity AND desktop's decryption identity.

### Operational impact

- `nixos-rebuild switch` on desktop: YubiKey plugged in, PIN typed at activation prompt.
- `reboot` on desktop: YubiKey must be inserted before boot reaches user-creation phase. Forget → boot fails with "no matching identity found" in the activation log.
- Lose the YubiKey: desktop can't boot. Recovery requires either a pre-registered second YubiKey or a rollback to the standalone-keyFile configuration on desktop.
